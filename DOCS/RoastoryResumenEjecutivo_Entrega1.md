Problemática

Actualmente, los pequeños negocios que combinan la venta de productos y
servicios, como una librería que además funciona como cafetería,
requieren herramientas tecnológicas que permitan administrar de forma
organizada la información relacionada con inventario, ventas, clientes y
facturación. La ausencia de un sistema centralizado dificulta el control
adecuado de los productos, genera inconsistencias en los registros y
limita la capacidad del negocio para realizar seguimiento de sus
operaciones, lo que afecta la eficiencia administrativa y la toma de
decisiones (Chicaiza y Pilicita, 2022).

En el desarrollo de sistemas empresariales modernos, la utilización de
aplicaciones web basadas en arquitectura cliente-servidor permite
integrar en una sola plataforma

diferentes procesos del negocio, facilitando el acceso a la información
y mejorando la gestión de los recursos. Tecnologías como Node.js,
Express y bases de datos NoSQL como MongoDB permiten construir
aplicaciones escalables capaces de manejar múltiples usuarios y grandes
volúmenes de información, lo cual resulta adecuado para sistemas
administrativos que requieren flexibilidad y mantenimiento sencillo (Ye,
2025). Además, el uso de aplicaciones web con comunicación asíncrona
entre el cliente y el servidor permite actualizar la información sin
necesidad de recargar la página, mejorando la experiencia del usuario y
permitiendo que los sistemas de gestión funcionen de manera más
eficiente en entornos donde se realizan ventas, consultas de productos y
generación de comprobantes en tiempo real (Chicaiza y Pilicita, 2022).
Debido a estas necesidades, se plantea el desarrollo de un sistema web
denominado Roastory, orientado a la gestión de una librería-cafetería,
el cual permitirá integrar en una sola aplicación el control de
inventario, el registro de clientes, la gestión de ventas, la generación
de facturas en formato PDF y la consulta de productos por parte de los
usuarios. La elección de una arquitectura basada en tecnologías web
modernas facilita el cumplimiento de estos requerimientos y se alinea
con las prácticas actuales en el desarrollo de software para sistemas de
gestión empresarial (Ye, 2025). 3. Actores del sistema Actor 1:
Administrador Es el usuario encargado de gestionar el funcionamiento
general del sistema. Puede registrar productos, actualizar el
inventario, administrar los usuarios, consultar reportes de ventas y
generar facturas. Se beneficia del sistema al tener un control
centralizado de la información del negocio. Actor 2: Empleado Es el
usuario que utiliza el sistema para realizar las operaciones diarias del
negocio, como registrar ventas, consultar productos disponibles y
generar comprobantes. El sistema le permite realizar estas tareas de
forma rápida y organizada, reduciendo errores en el proceso de atención
al cliente. Actor 3: Cliente Es el usuario que interactúa con el sistema
para consultar los productos disponibles en la librería-cafetería y
realizar compras. Se beneficia del sistema al poder visualizar

la información de forma clara y acceder a los servicios del negocio
mediante una interfaz web. 4. Diagrama de Casos de Uso

El diagrama de casos de uso del sistema Roastory representa de forma
visual la interacción entre los actores y las funcionalidades
principales del sistema. Se definieron tres actores principales:
administrador, empleado y cliente, los cuales interactúan con diferentes
módulos del sistema según sus permisos y responsabilidades. El
administrador tiene acceso a las funciones de gestión del sistema, tales
como iniciar sesión, gestionar usuarios, registrar productos, editar
productos, actualizar el stock, consultar ventas, generar facturas y
descargar comprobantes. Estas

funcionalidades permiten mantener el control general del funcionamiento
del negocio. El empleado interactúa con el sistema para realizar las
operaciones diarias, como iniciar sesión, consultar productos, registrar
ventas, confirmar compras y generar facturas. Estas acciones permiten
llevar el control de las transacciones realizadas en la
librería-cafetería. El cliente utiliza el sistema para consultar los
productos disponibles, iniciar sesión en caso de tener una cuenta y
confirmar compras. Estas funcionalidades permiten mejorar la interacción
del usuario con el negocio mediante una interfaz web. El sistema se
encuentra dividido en los módulos de usuario, inventario, ventas y
facturación, los cuales agrupan las diferentes funcionalidades
necesarias para el correcto funcionamiento de la aplicación. Cada caso
de uso fue nombrado utilizando la estructura verbo en infinitivo más el
objeto, siguiendo las recomendaciones para la elaboración de diagramas
de casos de uso en ingeniería de software. 5. Enlace al video:

7\. Conclusiones

\* Se identificó la necesidad de desarrollar un sistema web que permita
gestionar de manera organizada la información de una librería-cafetería,
debido a las dificultades que se presentan cuando no se cuenta con una
herramienta tecnológica centralizada. \* Se definieron los actores
principales del sistema, estableciendo los roles de administrador,
empleado y cliente, con el fin de determinar cómo interactúa cada
usuario con las funcionalidades del software. \* Se determinaron los
módulos principales del sistema, incluyendo usuario, inventario, ventas
y facturación, garantizando que cada integrante del equipo participe en
el desarrollo de una parte específica del proyecto. \* Se elaboró el
diagrama de casos de uso, el cual permite representar de forma visual
las funcionalidades del sistema y la relación entre los actores y cada
uno de los procesos definidos. \* Se estableció que el uso de
tecnologías web modernas permite desarrollar una aplicación escalable y
adecuada para la gestión de negocios, facilitando el control de
productos, ventas y generación de comprobantes. \* Se concluye que la
solución propuesta cumple con los requisitos planteados para la primera
fase del proyecto y proporciona una base adecuada para continuar con las
siguientes etapas de desarrollo.
